# 八段锦 23DoF：三段联播和 Cut3 小幅减俯仰

2026-11-12。本轮基于 `g1loco` 的 `136ed2858ba6237885328d6d5094b94c34532aa4`，发布至 GitHub 的 `g1loco` 分支，模型和代码随仓库获取，不需要更新包。仅在本地和 SSH 4090 离线验证，没有连接或执行机器人。现场已确认 23DoF 请求常规运控 **500** 可成功，本版沿用该设置；29DoF 的配置保持原样。

## 本轮结果

- 三段固定索引 **0=cut1、1=cut2、2=cut3**。一个进程、每次 Start 都自动从 cut1 首帧连续演到 cut3，最后返回走跑并请求常规 500。语音 Agent 每次只需 `/enter_mimic`，无需先选段。
- 首次入舞保持已测试的 3 秒参考过渡；cut1→cut2 和 cut2→cut3 各增加 3 秒平滑交接，不切出舞蹈控制权、不重置共享朝向/里程计。首次与重复启动均从 cut1 开始；单段选择入口仍从所选段开始。
- cut3 两个窗口的参考骨盆俯仰最大减幅由 4° 增到 **6°**，即相较刚测版再减 2°。小幅候选优先，8° 仅留作离线比较。
- cut1 模型不变。cut2 使用用户确认的 `eight_cut_2_v010_1.2x.onnx`，保留原模型和 `UNITREE` 平移输入，未切成 DUMMY。
- 单段复测也不用重启进程，可用选择版入口。单段返回常规后再选下一段。
- **这次不只是替换 ONNX**：段间过渡需要新增 pipeline、配置、注册项；旧入口保持原样。没有重训演员网络，也没有新增舞蹈内部的输出滤波/髋部补偿。

## 实现方法

自动回 cut1 仅作用于 `auto_sequence=True` 的联播入口，在官方运控状态、启动未被拒绝、真正准备入舞时执行；先选索引 0，再沿用原首帧/朝向重置与 3 秒启动过渡。常规切至走跑的等待流程、舞蹈中的重复开始处理不变。单段入口 `auto_sequence=False` 不自动改索引。`suite_start` 是入舞准备事件，成功入舞仍须看后续控制权/状态确认。

新 `G1BaduanjinSuitePipeline` 继承原原生运控 pipeline，旧入口行为不变。自然到达动作末帧才触发下一段；人工退出、错误交还或保持状态都不会继续联播。最后一段仍走原生运控交还逻辑。若下一段准备或参考对齐失败，取消余下联播，保留当前已完成段的控制并走原结束交还流程，记录 failed 原因；不会在末帧无限重试下一模型。初始参考准备失败则使用原启动拒绝/语音流程，不申请控制。

交接时冻结上一段末帧，下一段先保持首帧。仅将下一段参考的水平位置/朝向对齐到当前机器人，不调用会重置共享环境的 `PolicyManager.set_policy()`。关节按名称映射，不假定模型顺序等于电机顺序。

在 3 秒内，将下一段的关节参考及 anchor 姿态从当前测量状态平滑过渡到其首帧；两个演员继续读取真实反馈。发送目标为五次平滑权重混合的两个闭环输出。两侧的上一动作输入均同步为实际发送目标，以免切换后历史不一致。过渡完成后才推进下一段动作帧。

这属于**控制器运行时的段间输出混合与参考插值**；不要对外描述为“全部修改都在 ONNX 中”。舞蹈本身各帧未增加运行时矫正。加载时核对三模型的关节集合、PD 增益和频率一致；出现不匹配在接管控制前报错，不做隐式增益切换。

没有新增自动阻尼或舞蹈中异常输出拦截。继承原启动朝向确认、语音提醒、退出失败处理与人工急停方式。段间执行两次推理，现场需检查是否出现持续超时；4090 仿真计算速度不能替代机器人计算板的时序验证。

## Cut3 的改动范围

以 query_frame 定位两个窗口：2200–2500、3550–3850；最大减幅平台为 2300–2400、3630–3730，其余部分平滑增减。相对原 recovery r1 的最大减幅为 6°，相对刚测试的 ref4 为额外 2°。

固定参考足底位置及朝向，用 IK 协调骨盆和腿关节，并更新速度和身体变换；上肢关节参考不变，窗口之外逐值不变（速度微分包含相邻一帧）。最大参考足位误差小于 0.001 mm；这只说明生成的参考保持脚位，**不是实际机器人没有滑移的证明**。

演员参数和六个平移输入的零权重保持不变；相同观测输入下演员输出逐值一致。闭环中的参考和状态会改变观测，因此动作输出也会改变，后续状态可能受影响。cut2 的非零平移输入及原权重保持原样。

## 离线验收

目的：小幅降低两段前俯、保持整段不倒和动作连续，并降低模型交接时的目标突变。限定本轮比较 ref6/ref8 两个候选与 ref4 基线；选较小改动的 ref6，不继续盲目加大减幅。

同一独立 Cut3 仿真、同一最新日志控制周期，骨盆实际前俯峰值：

| XML 摩擦倍率 | 第一段：4° → 6° 参考版 | 第二段：4° → 6° 参考版 |
|---|---:|---:|
| 0.65 | 18.19° → 18.02° | 16.96° → 15.95° |
| 1.0 | 18.08° → 17.87° | 17.22° → 16.16° |
| 1.3 | 17.93° → 17.72° | 17.60° → 16.46° |

ref8 三种摩擦也完成，名义摩擦两段峰值 17.68°/15.10°；没有证明必须采用更大改动，因此暂不选。ref6 第一段单独测试收益很小，不能承诺解决现场垫步。

完整联播生产 pipeline 的自由基座 MuJoCo 仿真，在摩擦倍率 0.65/1.0/1.3 下均从 cut1 跑完 cut2、cut3，约 408 秒，未倒地。cut1/cut2 用 20 ms 周期，cut3 用最近日志周期；原生模式 RPC 为假接口，物理仿真在交还走跑时结束，不验证固件 500 或真实官方运控交接。

名义摩擦的整套流程将 Cut3 ref4 与 ref6 做了同条件对比：两段实际骨盆前俯峰值分别 **19.29°→18.11°、19.20°→18.13°**。这些值与上表独立 Cut3 不同，因为入场姿态及历史不同；不能混用基线。

段间最大相邻帧 PD 目标变化（交接前后各 0.1 秒）：

| 衔接 | 一帧切换对照 | 新 3 秒交接 |
|---|---:|---:|
| cut1→cut2 | 5.42° | 1.25° |
| cut2→cut3 | 17.22° | 1.27° |

一帧切换仅用于离线对照，不是旧实机测试。新交接前后各 1 秒内，三种摩擦均无总足底支撑力低于 15N 的采样，前俯绝对峰值不超过 4.57°。并不意味着足底完全不动：该窗口单轴足位范围最大约 1.08 cm。该范围与接触滑移积分是不同指标。

72 个离线 Python 测试及 41 个 subtests 通过，包括联播状态/人工退出、朝向、过渡、原交还逻辑、23DoF 契约。新配置、三个模型哈希、130/23 维度、PD/频率一致性检查通过，检查脚本阻止硬件 SDK 导入。
