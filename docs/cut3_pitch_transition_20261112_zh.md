## 为什么不是确认旧日志三次都请求 501

11 月 11 日这次 `motion.msgpack` 只有结果和 FSM 读回：三次尝试一直读到 801，最终 `-20003`。它没有逐次请求参数和 RPC ACK。仓库对应入口继承 `regular_fsm_id=501`，C++ 循环三次使用同一个参数，所以**现场代码与配置一致时三次都是请求 501**；不能把旧日志本身说成直接记录了三次 501。29DoF 现场“500 不成功、501 成功”的结果仍保留，不修改其入口。

新代码记录：

- Python `regular_loco_request.requested_fsm_id`，最终 `regular_loco` 同时保存请求 ID、结果和实际读回。
- C++ 标准错误输出 `FSM_REQUEST attempt=... requested_fsm_id=... request_result=...`。重新编译 bridge 并保存 stdout/stderr 后，可看到每一次真正的参数与 ACK。
- `fsm_trace` 仍为原来四列，未改变解析接口。读回 500 或 501 都属于当前桥接器的常规模式成功集合；成功不要求读回值与请求值相等。
- ACK 为 0 不是成功判据；最终仍要确认读回进入常规模式。不会自动在 500 与 501 之间轮换。

## 过渡实现及限制

直接将 PD 目标插值到静态关节角的原型在自由基座仿真中倒地，已拒绝采用。当前实现插值的是模型的**跟踪参考**：关节位置、相应导数及被观测使用的 anchor 朝向。模型仍每周期根据机器人反馈输出平衡动作。此参考命令不是经过完整 FK 重建的所有身体轨迹。

启动：重置朝向后，按关节名称将测量姿态从环境顺序映射到模型顺序；在确认 USER 控制权后计满 3 秒，插值到原模型首帧。过渡期间不推进舞蹈 query_frame，完成后开始原动作。不是播放视频时额外 sleep 3 秒。

收尾实验：保留当前测量骨盆朝向，避免沿用末帧腰部扭转要求机器人额外转身；插值到环境配置中保存的默认站姿，使用模型 metadata 覆盖环境前保存的值，避免误拿 actor 的 action offset。当插值结束后，继续闭环最多等待 3 秒：腿及腰的最大站姿误差 ≤0.20 rad、速度 ≤0.20 rad/s、骨盆 roll/pitch 均 ≤0.15 rad，并连续满足 0.3 秒，才交还 WALKRUN。失败保持并提示人工接管。这不是舞蹈中跌倒保护，不会请求阻尼，也不改变其他入口。

当前模型对新收尾参考有明显跟踪偏差。因此仅“多等 3 秒”或放宽确认阈值不能证明恢复成功；本轮现场先不启用收尾实验入口。后续需要专门适配/训练站姿过渡，并考虑保持足底落点，不能只把静态默认角度写进参考就当作解决。

## 离线结果及边界

基准与候选使用同一 MuJoCo 23DoF 背包模型、最新日志控制周期。下面均为仿真结果，不是真机测量，也不能据此判定现场摩擦系数。

| 条件 | 第一段骨盆前俯峰值，原版 → 新版 | 第二段骨盆前俯峰值，原版 → 新版 |
|---|---:|---:|
| 原 XML 摩擦 ×1.0 | 19.21° → 18.08° | 19.27° → 17.22° |
| 摩擦 ×0.65 | 18.86° → 18.19° | 18.94° → 16.96° |
| 摩擦 ×1.3 | 21.63° → 17.93° | 33.32° → 17.60° |

高摩擦第二段相邻 PD 目标最大跳变 74.40° → 5.39°；这是控制目标，不是实际关节瞬间转动。该段左右脚材料接触滑移积分分别约 13.51/16.67 cm → 5.01/3.96 cm。接触力及滑移均来自仿真。

另测试两段各一次局部扰动（前向速度 +0.14 m/s、俯仰角速度 +0.30 rad/s、额外目标延迟 15 ms、摩擦 ×0.8），原版及新版均完成；两段峰值分别 19.26° → 18.15°、19.18° → 17.15°。这是人工压力场景，不是真机扰动重放。

只启用启动 3 秒过渡的修改版 production pipeline，在摩擦 ×0.65/1.0/1.3 均完成整段。原生运控 RPC 在该测试中是模拟接口，**不验证固件接受 500 或真实交接稳定性**。启动是否减少真机抖动仍需 A/B 视频确认。

离线代码检查：7 个过渡测试、47 个原安全/交接测试、7 个原生入口集成测试通过；C++ 假 SDK 的 23/29DoF 各 34 场景通过；ONNX / 配置检查通过。没有实例化真实机器人 SDK 环境。
